再実行: `dotnet run --project tools/BalanceReview -- . docs/validation/m6`。シードはGameConfig.balanceReview.seed（202647）。

M5の自動操作と同じ必須優先・最寄り到達可能資源選択を使用。移動・採集・成長は通常のIGameServer.Tick、末尾の不足購入も所持金内でShop対象素材だけをBuyする。ルール・数量・資金・品質抽選・結果を書き換えない。操作判断はbotIntervalSecごと、到達時刻は終了時のOperationRecordを再生し、品質換算量が初めて目標を超えた正確なelapsedを使う（表は秒以下切捨て、JSONに小数秒を保存）。ボーナスは公開前には選ばない。

強化あり試行だけ、各ラウンドの目標生成後にplayer1が現在資金の50.0%以内でUpgradeを購入する。低Lv優先、同Lvはamount→luck→speed→move。planned-upgradesは各項目1Lv/Rまで、unlimited-budget-upgradesは予算内で回数制限なし。両方の結果を残す。ボットの強化は代行しない。目標はそのラウンド開始時の強化値で既に確定しており、購入で下げたり再抽選したりしない。これはbalanceReviewのQA操作方針で、通常の目標生成係数とは別。

## 目標生成と達成可能判定

素材別基準量の設定範囲を抽選し、roundGrowth^(R−1)、[1 + highestQualityWeight × (当該R最高品質 / R1最高品質 − 1)]、[1 + Σ(強化ごとのチーム平均Lv × upgradeWeights)]と[1 + upgradeSupplyWeight × max(0,実強化期待供給 / 同条件の無強化期待供給 − 1)]を掛ける。後ろの2項がチーム強化補正。実際の目標は、その結果と期待供給×maximumCapacityFractionの小さい方。係数の確定値は `balance.json` に同梱する。

供給シミュレーションは全員の5分を必須3種＋ボーナスに分け、実際のA*移動時間、往復、1訪問の採集回数、共有在庫と40秒再生、採集速度／量／運、バイオーム・資源の品質分布、有限回数の最高品質連続期待量を含む。候補不足や供給ゼロは再抽選／拒否する。品質の確率的な上振れ・下振れがあるので、『想定した能力と適切な操作の下での期待供給に収まる』保証であり、全乱数列・放置・無強化の勝利保証ではない。

単調性は素材抽選の違う総量を足して比較せず、同素材・同シード・同じ位置と資源状態で比較する。R1→R5は式の値に加え、上限適用後のGeneratePlanの返却目標も3シードで厳密増加を確認する。各強化は目標を下げず、4項目を増やした場合は全目標が厳密増加する。移動速度や採集速度だけを増やしても資源在庫が上限になる素材では、達成可能性を守るため同値を認める。

## 残るテンポ上の限界

計画的強化では後半も約2分の必須集めが必要になった。一方、予算だけを制限した投資では前Rのボーナス報酬を使って目標生成後に多数の強化を購入でき、R5は約12秒で必須を達成する。開始後の強化に合わせて確定目標を変更する仕様は追加しないため、このケースは残る。成功ケースだけを抽出せず、無強化R4失敗と投資による高速クリアを両方記録した。採集式、連続倍率、強化の上限、資金報酬は変更していない。
