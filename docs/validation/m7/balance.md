# M7 見込み強化を含む目標生成の自動操作記録

再実行: `dotnet run --project tools/BalanceReview -- . docs/validation/m7`。シードはGameConfig.balanceReview.seed（202647）。

M5の自動操作と同じ必須優先・最寄り到達可能資源選択を使用。移動・採集・成長は通常のIGameServer.Tick、末尾の不足購入も所持金内でShop対象素材だけをBuyする。ルール・数量・資金・品質抽選・結果を書き換えない。操作判断はbotIntervalSecごと、到達時刻は終了時のOperationRecordを再生し、品質換算量が初めて目標を超えた正確なelapsedを使う（表は秒以下切捨て、JSONに小数秒を保存）。ボーナスは公開前には選ばない。

強化あり試行だけ、各ラウンドの目標生成後にplayer1が現在資金の50.0%以内でUpgradeを購入する。実際の価格が安い順、同額はamount→luck→speed→move。planned-upgradesは各項目1Lv/Rまで、unlimited-budget-upgradesは予算内で回数制限なし。ボットの強化は代行しない。これはbalanceReviewのQA操作方針で、ゲーム側の強化制限ではない。

M7では目標生成前に、現在の共有資金の50.0%から購入できる見込みLvをCoreで計算する。IsBot=falseの人間だけに、同じUpgradeRulesの価格で安い順に仮配分する。予算は全人間で共有し、同額の優先順はobjectiveGeneration.anticipatedUpgradePriority、その次にactor順。実資金・Lv・履歴・乱数は変えない。生成時の見込みLvを目標補正と供給予測の両方に使い、生成済み目標は実際の購入後も固定する。QAの購入方針を参照して目標を変える処理はない。

## 目標生成と達成可能判定

素材別基準量の設定範囲を抽選し、roundGrowth^(R−1)、[1 + highestQualityWeight × (当該R最高品質 / R1最高品質 − 1)]、[1 + Σ(見込み強化ごとのチーム平均Lv × upgradeWeights)]と[1 + upgradeSupplyWeight × max(0,見込み強化期待供給 / 同条件の無強化期待供給 − 1)]を掛ける。後ろの2項がチーム強化補正。実際の目標は、その結果と見込み期待供給×maximumCapacityFractionの小さい方。M6の基準量・成長率1.35・品質補正0.35・容量率0.85・実効供給重み1は変更せず、見込み予算率0.5だけを追加した。全係数は `balance.json` に同梱する。

供給シミュレーションは全員の5分を必須3種＋ボーナスに分け、実際のA*移動時間、往復、1訪問の採集回数、共有在庫と40秒再生、見込み採集速度／量／運、バイオーム・資源の品質分布、有限回数の最高品質連続期待量を含む。見込み購入は開始資金で実行可能であり、購入そのものの採集時間コストは通常ルールと同じ0秒。ボットは現在Lvのまま。候補不足や供給ゼロは再抽選／拒否する。品質の上振れ・下振れがあるので、『購入可能な想定能力を使い、全員が適切に採る場合の期待供給に収まる』保証であり、全乱数列・放置・投資しない方針・現在の単純ボット方針での必勝保証ではない。

単調性は素材抽選の違う総量を足して比較せず、同素材・同シード・同じ位置と資源状態で比較する。R1→R5は式の値に加え、上限適用後のGeneratePlanの返却目標も3シードで厳密増加を確認する。各強化は目標を下げず、4項目を増やした場合は全目標が厳密増加する。移動速度や採集速度だけを増やしても資源在庫が上限になる素材では、達成可能性を守るため同値を認める。

## M6との比較と限界

M6の同シード・予算内無制限試行はR5を12.478390秒で達成した。今回のR5は106.602022秒（1:46）。大量投資後の採集力を目標が予見できず数秒で終わる問題を改善した。比較元は `../m6/balance.json`。

無強化と各項目+1Lv/Rの計画的試行も同条件で残す。後半に大きい共有資金があるのに投資しない場合は見込み能力へ届かず、失敗しうる。開始後に全資金を使う、安い順以外に集中投資する、品質連続が大きく上振れるケースの短縮はあり得る。見込み予算率はテンポ調整値であり、全プレイ方針のクリア時刻を保証しない。採集式、連続倍率、強化の上限、実購入価格、資金報酬は変更していない。
