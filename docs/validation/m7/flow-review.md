# M7 タイトルからR2までの通し録画レビュー

対象は [title_to_round2.mp4](title_to_round2.mp4)。動画から24時点をデコードして目視し、[前半の一覧](flow-contact-1.png)・[後半の一覧](flow-contact-2.png)へ保存した。遷移の欠落、結果からHomeへ戻る誤遷移、画面下ボタンの切れ、黒画面による中断は確認しなかった。最後はR2の採集画面に到達している。

## 録画条件とファイル確認

- Gameビュー390×844、H.264 / yuv420p、25fps。**無音の動画で、音声ストリームはない。** UIの音設定はON表示だが、この録画から効果音の内容・同期は評価しない。
- **ゲームの時計だけ10倍、芋煮会演出は1倍。** Waitingの参加待ち・Loading・画面遷移も実時間。R1の採集は通常のBootstrap.TickとIGameServer操作で進め、結果を注入していない。
- [flow-recording.json](flow-recording.json)はLibrary側のrecording.jsonとバイト一致。元の画像1936枚はすべて存在し、要求時刻は厳密に増加している。実時計の記録は77.9913535秒、平均撮影間隔0.040304秒。
- 最長の撮影間隔はWaiting→Loadingの0.260398秒。画像の間隔を保存したconcatから映像化しており、1936枚を単純に25fpsで再生して実時間を縮めていない。25fpsへ整えたMP4は1953フレーム・78.12秒。元画像数／実時計と、動画のフレーム数／コンテナ長を区別する。
- ffmpegで全編をデコードし終了コード0。98%以上が黒いフレームの40ms以上の連続は検出されなかった。manifestのConsoleはエラー0・警告0・ログ0。
- 動画SHA-256: `9A802D8BFD6D09E91EB4DA6C878EF17FADB8B4CAE74535D6B3913759021D0508`。

Waitingでは動画18.4／21.0／23.8秒の画像で人数増加を確認した。会員証の青い写真枠とWaiting/Loadingの無地の丸は既存モックのプレースホルダーであり、アバターの描画欠落として扱わない。

Gameでは動画31.7／34.4／43.0／50.0／59.0秒を比較し、プレイヤーに追従する地形の移動、採集ポップアップ、必須素材の増加、2分経過後のボーナス公開を確認した。タイムアップ後に採集画面のまま進行を続けず、演出とResultを経由してR2へ進む。

演出は開始から約1.5／4.6／9秒を確認した。実プレイの確定スコアを使うため、モック動画の固定18,420とはスコア・レベル到達時刻が異なる。完成時には結果ボタンが見え、Resultの数値と演出の最終スコアが一致する。結果の報酬欄が増えても下部のR2ボタンは画面内に収まっている。

## 確認範囲

24代表フレームの目視、全編デコード、manifestの遷移・時刻・通常ボタンクリック履歴を照合した。全1936枚を1枚ずつ目視した検査ではない。音声・Android実機の描画・操作応答はこの無音のEditor録画では評価しない。端末のSafe Area検証は同ディレクトリの `simulator/` に分けて記録している。
