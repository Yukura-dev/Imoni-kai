# 芋煮会演出 実装仕様（Imoni / ImoniFail）

**正解の見た目と動き**：`design/videos/imoni_success.mp4` と `design/videos/imoni_fail.mp4`（モックをそのまま録画した 390×844・約10秒の動画）。
Unity で作ったものを同じ長さで録画し、**並べて見比べ、違いがなくなるまで直す**こと。
数値は `GameConfig.imoniEffect`、ロジックの原本は `mock/Imoni.dc.html` の `step()` と `renderVals()`。

---

## 0. 不格好になる原因と対策（必読）
| 起きがちなこと | 原因 | 対策 |
|---|---|---|
| 鍋・柱・食材が全部 20px ずれる | モックは画面より20px外側に広げた枠（430×884、`inset:-20px`）を基準にした座標で書いてある | **下の数式はすべて画面座標（390×844、左上原点、下向きが +Y）に直してある。モックの数値を直接使わない** |
| 光の柱がただの白い帯になる | CSS の box-shadow（光彩）が UI Toolkit にない | `fx_pillar.png`（光彩込み）を使う |
| 虹色の背景が出ない・単色になる | linear-gradient がない | `fx_rainbow_scroll.png` を縦に流す |
| 鍋の後ろの回転する光がない | conic-gradient がない | `fx_sunburst.png` を回す |
| 食材や星が背景に埋もれて安っぽい | drop-shadow（白い光彩）がない | `ingredient_*_glow.png` と `fx_star_<色>.png`（光彩込み）を使う |
| 柱の横の虹色のにじみがない | blur がない | `fx_rainbow_glow.png`（ぼかし済み）を使う |
| 鍋が弾むと上に浮く | 拡大の中心が真ん中になっている | 鍋の要素の `transform-origin` を **(50%, 80%)** にする |
| 食材が回転すると位置が飛ぶ | 回転の中心が左上 | 食材と星は `transform-origin` を中心（既定値）にし、位置は `translate` で動かす |
| 文字の縁取りが細い・ない | CSS の text-shadow を4方向に重ねて縁取りにしている | `-unity-text-outline-width: 3px; -unity-text-outline-color: #8B2310;` ＋ `text-shadow: 4px 4px 0 #8B2310` |
| 環境によって速さや増え方が変わる | 毎フレーム一定の割合で動かしている | 経過時間（ミリ秒）から計算する。スコアのカウントアップは `disp += (score - disp) * (1 - pow(0.78, dt*60))` |
| 失敗時に色があせない | CSS の grayscale フィルターがない | 下の「6. 失敗版」の方法を使う |

## 2. 重ね順（下から）
1. **World**（揺れの対象。`translate(sx, sy)` を掛ける）
   1. 虹色の背景
   2. 放射状の光
   3. 光のライン（streak）
   4. 虹色のにじみ
   5. 光の柱
   6. キラキラ（sparkle）
   7. 食材
   8. 光の輪
   9. 鍋（汁面の光 → 鍋の画像）
   10. 星
2. **白フラッシュ**（画面全体）
3. **HUD**（音ボタン・スキップ・スコアカード）
4. **LEVEL UP バナー**、**完成の文字**、**結果ボタン**

※ 失敗版で色をあせさせる覆いは World の一番上、白フラッシュの下に置く（6章）。

## 3. 定数（画面座標）
- `CX = 195`（中心 x）、`POT_Y = 536`（食材の着地点・星や輪の中心 y）
- レベルの閾値：`TH[i] = round(levelThresholdRatios[i] × 成功時の最終スコア)`。失敗版でも同じ閾値を使う（だから Lv.3 で止まる）。
- 失敗版の最終スコア：成功時の約 40%（モックでは 7,350）。本番では実際のスコアを使う。
- `t` は開始からの経過ミリ秒。`L` は現在のレベル（0〜5）。

## 4. 毎フレームの計算（モックの式を画面座標にしたもの）
```
intro = min(1, t / 600)
pw    = ((56 + 16L) * intro + sin(t/90)*4 + (成功の完成後 ? 40 : 0)) * (1 - 0.85*gray)
        + (失敗の完成後 ? sin(t/30)*6*(1-gray) : 0)
glowOpacity   = intro * (0.35 + 0.12L)
burstOpacity  = ([0, .15, .30, .45, .60, .75][L] + (成功の完成後 ? .25 : 0)) * (1 - gray)
rainbowDur    = [5, 4, 3.2, 2.4, 1.7, 1.1][L] 秒
spinDur       = [14, 11, 8, 6, 4.5, 3][L] 秒

食材(1個ごと): p = min(1, (t - spawn) / fall)
  x = 171 + jx * (1 - p)                       // jx は生成時に -75〜+75
  y = -90 + 606 * (0.3p + 0.7p²)                // p=1 で食材の中心が y≈540(着地点)
  rotate = r0 + spin * p                       // r0: 0〜360, spin: -450〜+450
  scale  = 1.05 - 0.4p
  p が 1 になったら着地: スコア加算・星・音・レベル判定

小さい星(着地のたび、650ms): q = 経過/650、n = 5 + min(L,4)、i = 0..n-1
  a = -π/2 + (i - (n-1)/2) * π/(n+1) + (seed % 0.3)
  d = 14 + q * (60 + 12L)
  中心 = (bx + cos(a)*d, POT_Y - 6 + sin(a)*d + 30q²)   // bx = 195 + (-30〜+30)
  size = 14 + 2L、opacity = 1 - q、rotate = seed + 200q、色 = 6色を順番に

レベルアップ・成功の完成(1000ms): q = 経過/1000
  輪: 直径 = 60 + 700q、中心 (195, POT_Y)、opacity = 1 - q
  星14個: a = 2πi/14、d = 30 + 260q、中心 = (195 + cos(a)d, POT_Y + 0.8 sin(a)d)、size 26、rotate 360q

hitP     = (t - 最後の着地) / 180
potScale = hitP < 1 ? 1 + 0.06(1 - hitP) : 1
brothGlow = 0.4 + 0.1L + (hitP < 1 ? 0.3(1 - hitP) : 0)

lp    = (t - レベルアップ時刻) / 1400
flash = max(0, 1 - (t - レベルアップ時刻)/380) * 0.85   // 成功の完成後は max(flash, 1 - fp/600)
shake = max(0, 1-(t-レベルアップ時刻)/420)*10 + (L>=3 かつ 着地から90ms以内 ? 2.5 : 0)
        + (完成後500ms以内 ? (失敗 ? 6 : 12) * (1 - fp/500) : 0)
sx = sin(t/23) * shake,  sy = cos(t/19) * shake

LEVEL UP バナー(L>0、完成前、lp<1): 位置 y=300、全幅で中央そろえ、rotate -6°
  scale = lp<0.12 ? lp/0.12*1.25 : lp<0.22 ? 1.25-(lp-0.12)*2.5 : 1
  opacity = lp>0.8 ? (1-lp)/0.2 : 1
```
- **光のライン**：本数 `streakCount[L]`。1本ごとに次の値を最初に決めておく。
  - x：−20〜400
  - 幅：2〜5px
  - 長さ：90〜270px
  - 色：60% は白、残りは虹色
  - 不透明度：0.45〜0.95
  - 基本の周期 base：0.5〜1.1秒
  - 動き：y を −280 → 1080 へ、周期 `base / (1 + 0.28L)` 秒でループ。開始位置はランダムにずらす（CSS の負の animation-delay と同じ）。
- **キラキラ**：個数 `sparkleCount[L]`。1つごとに次の値を最初に決めておく。
  - 位置：x = 195 ± (45〜185) − 10、y = 70〜510
  - 大きさ：10〜26px
  - 点滅：周期 0.8〜1.7秒で、scale 0.1→1→0.1、opacity 0→1→0、rotate 0→90°。
  - 漂い：周期 1.2〜2.7秒で、y を 0 ↔ −60 に往復（ease-in-out）。

## 5. 成功版の最後
- 最後の食材が着地したら完成（または 8.2秒で強制的に完成）。
- 完成時にすること：白フラッシュ（0.6秒）、揺れ、光の輪と星14個、柱が +40px 太くなる、放射状の光を +0.25 濃くする、ゲージを100%にする。
- 「大成功!!」（Dela 26px・白・えんじの縁取り）と「芋煮\n完成!!」（Dela 58px・#FFE95C・えんじの縁取り＋白い光彩）を y=250 に出す。
  - 出方：拡大率を 0 → 1.15（0.3秒）→ 1.0（0.15秒）。
- 完成から 1.0秒後に「結果を見る」（深緑の大ボタン）と「もう一回見る」を下から28pxの位置に出す。

## 6. 失敗版の最後
- 完成（失敗）時から0.7秒かけて `gray` を 0→1 にする。
- **色あせ**：World の一番上に `rgba(125,116,102, 0.55×gray)` の覆いを重ね、さらに `rgba(0,0,0, 0.25×gray)` を重ねる。
  - 使っている Unity が UI 用のカスタムシェーダーに対応していれば、World を RenderTexture に描いてグレースケールにしてもよい。
- 光の柱は細くなりながらチラつく（4章の `pw` の式）。放射状の光は消える。白フラッシュはしない。揺れは弱め。
- 文字：
  - 「あれ…?」（Dela 22px・白・焦げ茶の縁取り）
  - 「芋煮\n未完成…」（Dela 52px・#DCD6CC・焦げ茶の縁取り）
  - 「必須素材『○○』が足りなかった」（実際に不足した素材名。焦げ茶の丸ラベル）
  - 出方：y を −80 から落とす（0.4秒、ease-out：`-80*(1-fp/400)²`）。
- 1.3秒後に「結果を見る」（焦げ茶）→ GameOver。

## 7. 音
UI_SPEC 12章の表のとおり。ドローンは開始0.3秒から鳴らし、完成時にフェードアウトする。

## 8. 確認方法（完了条件）
1. Unity の Game ビューを 390×844 にして、演出を録画する。
2. `design/videos/` の動画と横に並べ、次の点が一致していること。
   - 鍋・柱・着地点の位置
   - 色と光り方
   - レベルアップのタイミング
   - 最後の文字とボタンが出るまでの時間
3. どんな最終スコア（1、18,420、10^15）でも、10秒以内に結果ボタンが出ること（Core のテストでも確認する）。
