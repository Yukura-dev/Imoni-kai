# オンライン芋煮会 ゲーム仕様書 v1.0

**状態：基本設計完了・実装前レビュー版**

> このファイルはプロジェクトオーナーから受け取った仕様書の原文。
> 仮の数値の採用値と、モック作成時に決めた追加事項は `DECISIONS.md` を参照。

## 1. ゲーム概要

### 1.1 コンセプト

ランダム生成される2Dワールドでチームメンバーと協力し、採集・売買・個人強化を繰り返しながら、5回連続で芋煮会を成功させるオンライン協力ゲーム。

成長によるインフレをゲームの特徴とし、後半になるほど大量の資源と高品質素材を獲得できる。

### 1.2 基本構成

| 項目 | 仕様 |
|---|---|
| ジャンル | 2D協力型採集・育成・スコアアタック |
| チーム人数 | 基本3人（仮） |
| ワールド | チームごとに独立 |
| マップ | ランダム生成・段階拡張 |
| ラウンド | 1回5分 |
| 通常クリア | 5ラウンド連続成功 |
| 失敗 | 全リセットして最初から |
| クリア後 | エンドレスモード |
| 競争要素 | チームランキング |
| 操作 | タップによる自動移動・自動採集 |
| 体力 | なし |

**設計原則**

- 操作は簡単に、判断には戦略性を持たせる。
- 役割を固定せず、全員が自由に行動する。
- チーム全員が資源と資金を共有する。
- プレイヤーの強化と資源要求量の両方をインフレさせる。
- ランダム性は維持しつつ、理論上クリア可能な条件を生成する。

## 2. ゲーム進行

### 2.1 挑戦開始

1. チームを作成する。
2. ワールドシードを決定する。
3. バイオーム・地形・資源を生成する。
4. プレイヤーを開始拠点に配置する。
5. 初期資金と初期能力を設定する。
6. ラウンド1を開始する。

初期資金は1,000G、個人強化レベルは0と仮定する。

### 2.2 各ラウンド

**開始時（0:00）**

- 新しいエリアを開放
- 必須素材と必要数量を公開
- 最高品質の連続記録を0にする
- 5分間のタイマーを開始

**採集中（0:00〜2:00）**

- 各プレイヤーが自由に移動・採集
- 素材はチーム共有倉庫へ追加
- 売買と個人強化が可能
- 必須素材の達成状況を常時表示

**ボーナス発表（2:00）**

- ボーナス素材と目標数量を公開
- チーム全員に通知
- 既に倉庫にある対象素材も達成量として計上

**後半（2:00〜5:00）**

- 必須素材の不足を補う
- ボーナス目標を狙う
- 必要に応じて素材を売却・強化

**芋煮会（5:00）**

- 全プレイヤーの採集・売買を停止
- 共通倉庫の全素材を自動投入
- 必須素材の達成率を判定
- ボーナス評価を計算
- ランキングスコア・資金報酬を確定

### 2.3 成功と失敗

成功時は素材と連続記録をリセットし、共有資金・個人強化・マップ状態を引き継ぐ。

失敗時は現在の挑戦を終了し、素材・資金・強化をすべて初期化する。再挑戦時には新しいマップを生成する。

失敗した挑戦のスコアは正式ランキングに登録しない（仮決定）。

## 3. ワールド・マップ

### 3.1 基本構造

トップダウン視点の2Dタイルマップ。

ワールドは挑戦開始時にシード値を使用して生成する。5ラウンドの間は同じマップを維持し、ラウンドが進むと探索可能範囲が自動的に広がる。

チャンク単位で地形・資源を管理し、必要な部分だけクライアントへ送信する。

### 3.2 バイオーム

| バイオーム | 主な資源（仮） |
|---|---|
| 平野 | 里芋・ねぎ |
| 森林 | 薪・キノコ |
| 山岳 | 薪・山菜・希少キノコ |
| 河川 | 魚・水・水辺の植物 |
| 湿地 | 特殊なキノコ・植物 |

各バイオームでは、資源の出現率・数量・品質抽選の重みを変更する。

### 3.3 段階拡張

- R1：開始拠点周辺
- R2：探索範囲拡大
- R3：河川・森林などの追加エリア
- R4：山岳などの高効率エリア
- R5：通常モードの最大探索範囲

解放される具体的なバイオームは固定せず、生成されたマップに応じて変化する。

ただし、各ラウンドに必要な資源へ到達できることを保証する。

エンドレスモードではR6以降も探索範囲を拡張する。

### 3.4 マップの公平性

通常ランキングでは、各チームが異なるランダムマップを持つため、生成条件を統一する。

仮仕様として、ランキング用の共通シードを定期的に提供し、同じシード・同じチーム人数の挑戦を比較できる部門を設ける。

自由シードは別ランキングとする。

## 4. キャラクター操作・採集

### 4.1 基本操作

プレイヤーが資源オブジェクトをタップすると、キャラクターがその対象まで自動移動する。

到着すると自動採集を開始し、対象が採集不能になるまで継続する。

別の対象をタップすると現在の行動を中断し、新しい対象へ移動する。

### 4.2 移動

- 経路探索によって障害物を回避
- 移動速度は個人強化で増加
- 移動中は採集しない
- 移動先が採集不能になったら停止
- 到達できない対象は選択できない

経路探索にはA*を初期候補とする。

### 4.3 資源採集

資源オブジェクトには以下の情報を持たせる。

- 資源ID
- 資源の種類
- 所属バイオーム
- 成長段階
- 残り採集可能量
- 再生時間
- 品質抽選補正
- 採集効率補正

### 4.4 段階成長

例：木

切り株 → 苗木 → 若木 → 成木 → 採集可能

採集後は切り株へ戻り、再成長する。

成長段階と再生時間は資源の種類ごとに管理する。

ラウンドが変わってもワールド内の成長状態を維持する。

### 4.5 複数人での同時採集

同じ資源オブジェクトに複数人がアクセスできる。

採集作業量をサーバーが管理し、作業に応じて素材を獲得する。

素材は直接チーム共有倉庫へ追加するため、プレイヤー間で分配する必要はない。

## 5. 素材・品質システム

### 5.1 品質ランク

同じ素材にも複数の品質が存在する。

初期案は以下とする。

| 品質 | 品質倍率 | 初回解放 |
|---|---:|---|
| 普通 | ×1 | R1 |
| 良質 | ×2 | R1 |
| 希少 | ×5 | R1 |
| 伝説 | ×20 | R2 |
| 神話 | ×100 | R3 |
| 超越 | ×1,000 | R4 |
| 究極 | ×10,000 | R5 |

品質ランク・倍率・解放順は仮設定。

エンドレスモードではさらに上位品質を追加できるよう、データ駆動で定義する。

### 5.2 品質抽選

品質確率は、以下の条件で変化する。

- 個人の採集運レベル
- バイオームの品質補正
- 資源オブジェクトの品質補正
- 現在解放されている品質ランク

品質ごとの抽選重みを計算し、正規化して抽選する。

最高品質の確率には人為的な上限を設定しない。

### 5.3 品質換算数量

素材の品質は、必須素材とボーナス素材の達成率に共通して適用する。

品質換算数量：

`Σ（実数量 × 品質倍率）`

例えば伝説品質×20の里芋1個は、普通品質20個分として扱う。

## 6. 最高品質連続ボーナス

### 6.1 基本仕様

- プレイヤー個人ごとに管理
- そのラウンドの最高品質を引くと連続回数+1
- 最高品質以外を引くと0に戻る
- 素材の種類や採集場所を変更しても継続
- 毎ラウンド開始時に0へリセット
- 過去に獲得した素材とポイント倍率は保持

### 6.2 指数成長

仮の倍率：

`連続倍率 = 2 ^ (連続回数 / 10)`

素材獲得数量と素材ポイントに、それぞれ連続倍率を適用する。

採集時には数量倍率を計算し、増加後の実数量を倉庫に追加する。

ポイント専用倍率は採集時に記録し、芋煮会で使う。

### 6.3 数量計算

`実獲得数量 = floor(基本獲得数量 × 数量連続倍率)`

### 6.4 素材ポイント

`素材ポイント = 実獲得数量 × 素材基本ポイント × 品質倍率 × ポイント連続倍率`

この計算によって、連続ボーナスは数量とポイントの両方に反映される。

### 6.5 数値の扱い

大量の素材やスコアを扱うため、数量・資金・確定ポイントは大きな整数に対応する。

実装では整数演算と倍率の固定小数点表現を優先し、浮動小数点誤差による不一致を避ける。

## 7. チーム共有倉庫

### 7.1 共有対象

- 採集素材
- チーム資金
- 素材のロック状態

個人強化と連続記録は個人ごとに保持する。

### 7.2 素材の管理単位

基本管理単位は、素材種類・品質・獲得時のポイント倍率を持つ素材ロット。

同じ種類・品質でも、ポイント倍率が違う場合は計算上区別する。

### 7.3 売却

売却価格：

`売却額 = 売却数量 × 基本売却価格 × 品質倍率`

連続ボーナスで増加した数量は売却対象に含める。

ポイント専用連続倍率は売却額に掛けない。

### 7.4 売却操作

- チーム全員が売却可能
- 確認画面なしで即時売却
- 数量直接入力に対応
- 25%・50%・75%・100%の割合指定に対応
- 個別売却に対応
- 複数素材の一括売却に対応
- 売却結果を全員に即時同期

### 7.5 素材ロック

素材の種類・品質・数量ごとに保護数量を指定できる。

チーム全員が設定・変更・解除できる。

ロック数量を下回る売却は禁止する。

ロック中の素材も芋煮会には投入される。

同じ種類・品質で複数ロットがある場合、売却可能なロットを古い獲得順から消費する方式を仮採用する。

### 7.6 同時操作

売却・ロック変更・共有資金の使用は、サーバー側で原子的に確定する。

チーム全員の端末には、確定後の状態を同期する。

操作履歴には実行者・種類・数量・時刻を記録する。

## 8. 資金・個人強化

### 8.1 共有資金

資金はチーム全員が自由に使用できる。

主な使い道：

- 個人強化
- 素材購入
- 将来的な特殊アイテム

### 8.2 個人強化

| 強化 | 効果 |
|---|---|
| 移動速度 | 移動時間の短縮 |
| 採集速度 | 対象の採集時間短縮 |
| 採集量 | 1回あたりの素材数量増加 |
| 採集運 | 高品質素材の抽選確率向上 |

能力のレベル上限は設けない。

強化価格はレベルに応じて上昇する。

仮の価格式：

`価格 = 基本価格 × 1.5 ^ 現在レベル`

各能力の係数はプレイテストで調整する。

### 8.3 資金運用の戦略

序盤は個人強化への投資を優先し、終盤は芋煮会の得点を優先する、といった判断が可能になる。

チームの役割分担は固定しない。

## 9. 芋煮会・成功判定

### 9.1 ランダム目標

必須素材とボーナス素材は、毎ラウンドランダムに決定する。

必須素材と数量は開始時に公開する。

ボーナス素材と数量は2分経過時に公開する。

同じ素材が同一ラウンドで必須・ボーナスの両方に選ばれることは、初期仕様では禁止する。

### 9.2 目標生成

抽選対象は、現在開放されているエリアで入手可能な素材に限定する。

マップ・チーム人数・採集効率・移動時間・資源再生を考慮して要求量を生成する。

抽選アルゴリズムは、まず達成可能な目標候補を構築し、その範囲からランダムに選択する方式とする。

シミュレーションで達成可能性を検証し、不適切な条件は再抽選する。

ここでの保証は、想定された能力と適切な操作で成功可能な構成を生成することを意味し、プレイヤーの成功を保証するものではない。

### 9.3 必須素材の成功判定

すべての必須素材について、品質換算数量が必要数量以上であることを成功条件とする。

1種類でも不足すれば失敗。

### 9.4 ボーナス素材

必須素材とは別に、品質換算数量による達成率を計算する。

ボーナス達成率に応じて段階報酬を付与する。

例：

| 達成率 | 報酬倍率（仮） |
|---|---:|
| 100%未満 | ×0 |
| 100%以上 | ×1 |
| 150%以上 | ×2 |
| 200%以上 | ×4 |
| 300%以上 | ×8 |

ボーナス報酬はチーム資金とランキングスコアの両方に反映する。

## 10. スコア・ランキング

### 10.1 基本方針

- スコアのインフレを許容
- 素材ごとに異なる基本ポイント
- 品質倍率を反映
- 連続ボーナスを反映
- 必須素材とボーナス素材の基本配点は50：50
- 5ラウンドのスコアを単純合計
- スコアを達成率で正規化しない

### 10.2 スコア計算案

素材ロットごとに、採集時に確定した数量・品質・ポイント倍率から素材ポイントを計算する。

必須素材のポイント合計を `R`、ボーナス素材のポイント合計を `B` とする。

ボーナス達成率による段階倍率を `T` とする。

仮のラウンドスコア：

`ラウンドスコア = 0.5 × R + 0.5 × B × T`

この50：50は基本係数の比率であり、素材数量やボーナス倍率によって実際の得点比率は変動する。

ボーナスの資金報酬は別式で計算する。

**重要：売却済み素材はR・Bのどちらにも含めない。**

### 10.3 ランキング

通常モードは、5ラウンド連続成功した挑戦の合計スコアを記録する。

エンドレスモードは別ランキングとし、到達ラウンドと累積スコアを記録する。

同条件で比較できるよう、共通シード部門と自由シード部門を分離する（仮）。

## 11. マルチプレイ・通信

### 11.1 ワールドの分離

1チームにつき1ワールドインスタンスを管理する。

他チームのプレイヤーや資源は同じワールドに出現しない。

他チームとの競争はランキングで行う。

### 11.2 サーバー管理

以下はサーバーを正とする。

- ラウンドタイマー
- ワールド・資源状態
- プレイヤー位置
- 採集判定
- 品質抽選
- 共有倉庫
- 売却
- 資金
- 個人強化
- スコア計算

クライアントは移動・採集・売買などの操作を送信し、サーバーの確定結果を表示する。

### 11.3 同期

リアルタイム通信にはWebSocketを基本候補とする。

操作時はイベントを送信し、プレイヤー位置や進行状態は適切な頻度で配信する。

### 11.4 退出・再接続

仮仕様：

- 一時切断してもチームのゲームは継続
- 再接続すると現在のワールド状態を復元
- 切断中のプレイヤーは新しい採集を行わない
- 残りメンバーはゲームを続けられる
- 挑戦途中の新規参加は原則禁止

## 13. データ構造案

主なデータモデル：

| モデル | 主要データ |
|---|---|
| Team | ID、メンバー、共有資金、状態 |
| Player | ID、チームID、位置、個人強化、連続記録 |
| World | ID、シード、生成設定、解放範囲 |
| ResourceNode | ID、位置、種類、成長段階、残量 |
| MaterialLot | 素材ID、品質、数量、ポイント倍率 |
| Inventory | チームID、素材ロット |
| MaterialLock | チームID、素材ID、品質、保護数量 |
| Round | 番号、開始時刻、終了時刻、状態 |
| Objective | 素材ID、必要数量、必須・ボーナス区分 |
| Transaction | 実行者、操作、数量、資金変動 |
| RunResult | 挑戦ID、ラウンド結果、累積スコア |

素材ロットの数量・倍率は、インフレを考慮して大きな整数を扱えるようにする。

## 15. 受け入れテスト

実装完了を判定するため、最低限以下を満たす。

1. 3人が同じチームに参加し、同じマップ状態を確認できる。
2. 別チームのワールドとは資源や資金が混ざらない。
3. 資源をタップすると移動し、到着後に自動採集する。
4. 1人の採集結果が全員の倉庫に反映される。
5. ロック数量を下回る売却が発生しない。
6. 複数人の同時売却で数量や資金が不正にならない。
7. 品質・連続ボーナスの抽選と計算が再現可能である。
8. 2分経過時にボーナス目標が公開される。
9. 5分経過時にサーバーが採集を停止して判定する。
10. 必須素材不足ならラウンド1へ戻り、挑戦データが初期化される。
11. 5ラウンド連続成功で通常クリアになる。
12. 確定スコアに売却済み素材が含まれない。
