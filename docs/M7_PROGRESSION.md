# M7 二つ名・バッジ・ローカル記録

条件の数値は `Assets/Imoni/Config/GameConfig.json` の `progression` を唯一の定義元とする。確定した `RoundResult` の採集履歴を `PlayerProgression` が評価し、画面は評価結果を表示する。新しい二つ名はResult/Clearの既存報酬欄に表示し、選択中の二つ名を勝手に変更しない。複数を同時獲得した場合は1件目と「ほかn件」の最大2行にまとめる。全名称はtooltipと会員証の所持パーツ一覧で確認でき、1件時の表示は従来どおり。

## 二つ名の仮条件

初期所持は前半「芋煮会の」、後半「初心者」。追加のパーツは成功結果で条件を満たした時に付与する。採集数は本人の実採集数量の累計で、購入・他のメンバーの採集は含めない。

| パーツ | 条件 | Configのmetric / minimum |
|---|---|---|
| 前半 山の | R2以上を成功 | successfulRound / 2 |
| 前半 連続の | 本人の最高品質10連続 | bestStreak / 10 |
| 前半 伝説の | 通常モードを1回クリア | normalClears / 1 |
| 前半 神話の | R7以上を成功 | successfulRound / 7 |
| 前半 究極の | R10以上を成功 | successfulRound / 10 |
| 後半 薪割り職人 | 本人が薪を累計30個採集 | materialGathered / 30 / wood |
| 後半 里芋ハンター | 本人が里芋を累計30個採集 | materialGathered / 30 / taro |
| 後半 鍋奉行 | 初めてラウンドを成功 | successfulRound / 1 |
| 後半 採集王 | 本人が全素材を累計300個採集 | gatheredTotal / 300 |
| 後半 芋煮マスター | 通常モードを3回クリア | normalClears / 3 |

## バッジの仮条件

| バッジ | 条件 |
|---|---|
| はじめの一歩 | 初めてラウンドを成功 |
| R3到達 | R3を開始。途中で中断しても到達は保持 |
| 10連続 | 本人の最高品質連続が10以上 |
| 5連続成功 | 通常モードを1回クリア |
| 1億点 | 成功結果の累積スコアが100,000,000以上 |
| 究極品質 | 本人が究極品質を採集 |

採集・連続・品質の個人実績は失敗したラウンドからも保存する。失敗は成功回数・通常クリア回数・最高成功スコアを増やさず、二つ名の付与とランキング登録も行わない。会員証の裏に実際の取得状態を表示する。

## 保存と移行

プロフィールとランキングは既存の `imoni-profile.json` にまとめ、同じ一時ファイル置換で保存する。名前・配色・選択二つ名・音設定・チュートリアル完了状態は維持する。数量・スコア・クリア回数は `BigInteger` で保存し、表示だけ `Format.Big` を使う。

新しい挑戦にはUI側で固有IDを発行する。`挑戦ID:ラウンド` を保存済み結果キーにし、結果画面の再表示や保存後の再読込で採集数・クリア回数・報酬を再加算しない。同じシードを別の挑戦で成功した場合は別記録として扱う。ゲームの乱数列はこのIDに依存しない。

M5/M6の所有配列はそのまま引き継ぐ。所有配列がなかった旧形式では、保存されていた選択中の二つ名がカタログに存在する場合だけ所持へ移行する。旧モックの未保存のバッジ・最高R3・ダミーランキングは実績として移行しない。

## ランキング

通常 / エンドレス × 共通 / 自由シードの4部門を分離する。全行がこの端末で実際に確定した記録であり、M2bのダミー行は使わない。記録がない時は空状態を表示し、自分の欄は「未登録」。見出しにも「端末内」を表示する。

- 通常は通常モードR5成功時の累積スコアを自動登録する。
- エンドレスはR6以降の成功結果から「記録してホームへ」を選んだ場合のみ登録する。各ラウンド成功時には仮記録を追加しない。
- 失敗・採集中の中断は登録しない。通常クリア後に続けたエンドレスが失敗しても、それ以前に完成した通常クリア記録は残る。
- 通常はスコア降順。エンドレスは到達ラウンド降順、次に累積スコア降順。同値は記録日時の古い順、最後に挑戦ID順で安定させる。
- 共通シードの数値が一致しない記録は共通部門へ登録できない。現在の共通部門は現在のシードで絞る。自由部門では各行にシードを表示する。
- 人数別・部門別（共通はシード別）に `rankingLimitPerBoard=100` 件を保持する。記録日時はUTCで保存し、画面では端末の現地時刻をモックと同じ形式で表示する。

## 補完した画面と操作

UI_SPEC 15章の通常Clearと音量設定は既存のものを継続利用する。新しいLogin/Endlessも既存のCard、MemberCard、StatCard、AnimatedPot、ImoniText、ImoniButtonだけで構成する。再接続表示は別担当のGame内表示を使う。

1. Mainの「タップしてはじめる」→ `Login`。「この端末の会員プロフィール」を明記し、外部認証は行わない。
2. 初回は「会員登録をはじめる」→ Tutorial1〜3 → Home。登録済みは「この会員で続ける」→ Home。「会員登録・遊び方を見る」は保存を保持してTutorial1へ。
3. Homeの設定→「会員プロフィール」でもLoginへ戻れる。
4. 通常R5成功→Clear。通常記録とクリア実績が保存され、Homeのエンドレス選択が解放される。
5. Clearの「エンドレスへ」→ `Endless`。引継ぐ累積スコア・資金と記録条件を確認し「ラウンド6へ」→ Game。同じマップ・成長・資金・強化・スコアを保持する。
6. 解放後にHomeでエンドレスを選んで新しく開始した場合は、新しいマップ・初期資金・強化Lv0のR1から挑戦する。画面見出しは「エンドレス Rn」。通常R5で終了せず続行できる。
7. エンドレスの成功結果は「ラウンドnへ」で継続、R6以降は「記録してホームへ」で正式登録して終了できる。
8. 失敗後の「R1から再挑戦」は選択モードを維持し、新シード・新マップ・初期資金・強化Lv0へ戻す。通常へ戻す場合はHomeのモード選択を使う。
9. Rankingでモード・シードを切り替え、4部門の実記録/空状態を確認。再起動後も同じ記録・所持パーツ・バッジを確認する。

検証用の安定名: `LoginContinue`, `LoginTutorial`, `EndlessStart`, `EndlessHome`, `ResultEndless`, `ResultFinishEndless`, `ResultNext`, `home-mode-selector`, `ranking-mode`, `ranking-seed`, `ranking-list`, `ranking-mine-state`。`ScreenContext.EndlessSelected/EndlessUnlocked/ChallengeId`、`PreviewResultRewards`、`IGameServer.StartEndless/FinishEndless` を公開している。

## Core検証

### Resultの4件同時獲得で見つかった表示崩れ

SimulatorでのR1成功時に「薪割り職人」「里芋ハンター」「鍋奉行」「採集王」が同時に解放された。最初の撮影 `Library/M7-iphone_Result.png` では全名称をつないだ本文が長く折り返され、ResultSummaryが縦に伸びて `ResultNext` をSafe Areaの外へ押し出した。

修正後の投影は `「薪割り職人」GET!` と `ほか3件` の2行にする。元の全名称は `RoundResultView.NewTitleText` とResultSummaryのtooltipに保持し、所持パーツ自体を省略しない。既存NumericLabelFitterが必要な場合だけ最長行の文字幅を合わせ、1件獲得時の文言・見た目は変更しない。

追加した `MultipleTitleRewardsUseTwoSummaryLinesAndPreserveAllNamesForDetails` は、実際の4件の条件を満たすCore結果を使い、2行の要約と全4名称の保持を検証する。Simulatorでの再撮影とボタンがSafe Area内に収まる最終確認は、M7全体の画面検証に含める。

### テスト結果

実行コマンド:

```text
dotnet test tools/CoreTests --filter "FullyQualifiedName~ProgressionRankingTests|FullyQualifiedName~ProfilePersistenceTests|FullyQualifiedName~RoundFlowTests" --no-restore --verbosity minimal
```

結果: **46件成功 / 失敗0 / スキップ0**。その後の複数二つ名の表示修正では新規ケースを1件追加し、`ProgressionRankingTests|RoundFlowTests` を再実行して **40件成功 / 失敗0 / スキップ0**。最終的な新規 `ProgressionRankingTests` は23ケース。既存Profile7件は変更後の保存移行を含めて成功、RoundFlow17件も成功。全件とUnityでの表示・操作検証はM7全体の検証記録で報告する。

追加したテストの対象:

- 新規/旧形式保存の初期状態、選択二つ名の移行、既存所有保持。
- 初成功の新二つ名・バッジ、保存をまたぐ一度だけの付与、選択維持。
- 複数同時獲得時は2行に要約し、全名称を詳細用に保持すること。
- 到達時点の最高R/バッジ保持と中断時の不登録。
- 本人・当該ラウンドの採集だけを計上し、購入・ボット・過去履歴を除外。
- 素材別/総採集数とConfigで変更した条件の境界。
- 通常クリア回数の重複防止、エンドレスR5の除外、3回クリア報酬。
- R7/R10の二つ名、1億点バッジ、10^100を超える正確な保存。
- 失敗時の個人バッジ保持と二つ名/スコア実績/登録の禁止。
- 登録可能なモード・ラウンド・終了操作の6条件、両モードの失敗2条件。
- 4部門分離、エンドレスの到達R優先順、Config上限・再読込・登録の冪等性。
- 共通シード偽装の拒否、エンドレス失敗後の既存通常記録保持。
- 通常Clear→同じワールドR6、引継ぎ、成功境界だけで終了できること。
- 新規エンドレスR1、失敗/中断からの登録終了拒否、同モードの新シード再挑戦。
